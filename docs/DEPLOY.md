# Deploying SplitLah to Cloudflare (Workers Builds)

`main` deploys automatically to Cloudflare Workers, and every pull request gets its own Preview URL.
Builds run on Cloudflare's servers straight from GitHub; there is no GitHub Actions workflow and no
secret to store in GitHub. Everything here stays on Cloudflare's **free plan**.

The owner does the dashboard part once. Claude Code can't click the dashboard.

Checked against Cloudflare's docs on 10 Nov 2026 (Workers Builds pages updated 28 Oct–8 Nov 2026).
Dashboard labels change from time to time: if a field is named slightly differently, use the one
with the same purpose. The values to enter are the important part.

## What's in the repository

| File | Purpose |
|---|---|
| `cloudflare/wrangler.jsonc` | The Worker config: name `splitlah`, pinned compatibility date, the build output to deploy, workers.dev and Preview URLs. No bindings, secrets or paid features. |
| `src/server.ts`, `src/lib/security-headers.ts` | Security headers (CSP etc.) on pages the Worker renders. Only switched on by the `SPLITLAH_SECURITY_HEADERS` variable in the Cloudflare config, so the Lovable-hosted app is unchanged. |
| `public/_headers` | `nosniff` and `Referrer-Policy` on static files. |

The config is in `cloudflare/`, not the repository root, on purpose. The build tool (nitro) merges
any root-level `wrangler.json(c)` into the config it generates, including inside Lovable's own
build. Keeping it in a subfolder means Lovable's deploy is not affected while Lovable stays live.
That's why every Wrangler command below includes `--config cloudflare/wrangler.jsonc`.

## Before you start: order of steps

The production build reads `cloudflare/wrangler.jsonc` from `main`, so **merge the Batch D pull
request first**, then connect Cloudflare (steps 1–3). The first build then deploys `main` straight
away.

If you'd rather see it working before merging, see "Optional: try it before merging" at the end.

## 1. Create a free Cloudflare account

1. Go to <https://dash.cloudflare.com/sign-up> and sign up with your email and a password.
2. Verify your email address (Cloudflare sends a link).
3. You don't need to add a domain, choose a paid plan or enter a card. Workers Free is enough.

## 2. Import the GitHub repository

1. In the dashboard, open **Workers & Pages**, or go to
   <https://dash.cloudflare.com/?to=/:account/workers-and-pages>.
2. Select **Create application**.
3. Select **GitHub**.
4. When asked, install and authorise the **Cloudflare Workers and Pages** GitHub app. On GitHub's
   screen, choose **Only select repositories** and pick `strong0-23/Project-SplitLah-v-0.1`.
   (Cloudflare recommends limiting the app to the repositories you deploy.)
5. Back in Cloudflare, select `strong0-23/Project-SplitLah-v-0.1` from the list.

## 3. Configure the project, then Save and Deploy

Fill in these fields **before** selecting **Save and Deploy**:

| Field | Value |
|---|---|
| Project name / Worker name | `splitlah` (must match `name` in `cloudflare/wrangler.jsonc`, or the build fails) |
| Git branch (production branch) | `main` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler@4.154.0 deploy --config cloudflare/wrangler.jsonc` |
| Preview command (non-production branches) | `npx wrangler@4.154.0 preview --config cloudflare/wrangler.jsonc` |
| Root directory | leave empty (repository root) |
| API token | let Cloudflare create one (the default) |
| Build variables | add `NODE_VERSION` = `22.23.4` |

Notes:
- **Don't leave the default deploy command** (`npx wrangler deploy`). Without `--config` it would
  deploy with a config generated by the build, under a different name, and fail the name check.
- **Wrangler is pinned** (`@4.154.0`) because it isn't a project dependency. Cloudflare otherwise
  uses the version in `package.json`, and the project has none. 4.154.0 is the version these
  commands were tested with; Previews need 4.135.0 or later.
- **`NODE_VERSION`** pins Node to the version the build was tested with. Cloudflare's default is
  Node 24, and 22.23.4 is pre-installed in its build image.
- **Installing dependencies** is automatic. Cloudflare sees `bun.lock` and installs with Bun 1.4.4,
  the same version used for the checks.

Select **Save and Deploy**. The first build takes a few minutes. Watch it under the Worker's
**Deployments** tab, then **View build history**.

## 4. Turn on Preview builds for pull requests

1. Open the Worker `splitlah`, then **Settings**, then **Build**, then **Branch control**.
2. Make sure the production branch is `main`.
3. Tick **Enable Preview Builds**.

From now on, every push to a branch other than `main` runs the build and the Preview command. If the
branch has a pull request, Cloudflare comments on it with the Preview URL, and a check run appears
on the commit.

If a pull request comment says **No Preview URL**, open the Worker's **Domains** tab and, under
**Worker URL**, turn on **Preview**. `cloudflare/wrangler.jsonc` already asks for workers.dev
Preview URLs (`preview_urls: true`), so this should already be on after the first deploy.

## 5. Check the live app

1. Open the Worker's URL: `https://splitlah.<your-subdomain>.workers.dev`. Your account's subdomain
   is shown on the **Workers & Pages** page as **Your subdomain** (select **Change** to rename it).
2. Scan a receipt with your phone, check the review screen, then do a split and open the summary.
   The first scan downloads the OCR model (a few MB) from jsDelivr. The photo itself stays on the
   phone.
3. Optional: in a desktop browser, open DevTools → Network, select the page request, and check
   that the response has a `content-security-policy` header.

## 6. Retire Lovable (owner only, after step 5)

Lovable stays live until you're happy with the Cloudflare URL. Then retire it in Lovable's own
settings (unpublish the app and/or disconnect its GitHub sync). This repository doesn't change for
that.

## Costs and limits (free plan)

| | Free plan limit |
|---|---|
| Requests | 100,000 per day |
| CPU time | 10 ms per request |
| Worker size | 64 MiB (this app: about 1.7 MiB, 383 KiB compressed) |
| Build minutes | 3,000 per month, one build at a time, 20-minute timeout |
| Previews | 100 per Worker (the oldest are deleted automatically) |

Nothing here needs a paid plan. If Cloudflare ever asks you to upgrade or add a card for this
project, stop and decide first. Don't upgrade just to make a build pass.

Server-side rendering has to fit in 10 ms of CPU per request on the free plan. If you see errors
(Worker → **Metrics** → **Errors** → **Invocation Statuses** shows "Exceeded CPU Time Limits", or
the browser shows error 1102), report it rather than upgrading: there are free fixes to try first.

## Rolling back

Worker → **Deployments** → the three-dot menu next to an earlier version → **Rollback**. To stop
automatic deploys, Worker → **Settings** → **Builds** → **Disconnect**.

## Optional: try it before merging

To see the Cloudflare URL before merging the Batch D pull request, temporarily set the production
branch (step 3, "Git branch") to `deploy/cloudflare`. After you merge, change it to `main` under
**Settings** → **Build** → **Branch control**.

## Running the same checks locally

```powershell
npm.cmd run build
npx.cmd wrangler@4.154.0 deploy --dry-run --config cloudflare/wrangler.jsonc
npx.cmd wrangler@4.154.0 dev --config cloudflare/wrangler.jsonc
```

`wrangler dev` serves the built app at http://localhost:8787 with the same headers as the live site.
